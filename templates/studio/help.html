Decision-rule experiments

Decision-rule presets can now be applied as named experiments. Add a label and hypothesis when testing Aggressive Growth, Conservative Quality, Balanced Learning, or Lead Magnet Focus, then record the outcome from decision-rule history after reviewing performance.

Open decision-rule history · Compare decision-rule snapshots · Saved comparison reports

Use snapshot comparison when you want to inspect several decision-rule experiments or time windows at once. The comparison page shows summary deltas, full metric rows, and keep/rollback/inconclusive recommendations for the active rules plus any selected presets. Save important comparisons as named reports so they can be revisited, annotated, and exported later.

Saved comparison reports now include a print-optimized view. Use Printable report from a saved report detail page when you need a clean visual summary for a meeting, browser printing, or saving as a PDF.

When a report moves from analysis to action, update its report-level decision status to Keep, Roll back, Watch, or Archived. Add a short decision summary, owner, and notes so the saved report becomes a durable decision record.

The recommended daily workflow

  1. Create the lesson.Add enough structure to describe the teaching goal. Keep it in Draft while working.
  2. Add content blocks.Build the explanation in the same order a learner should read it.
  3. Review the source lesson.Confirm that code, output, terminology, and difficulty are accurate before generating anything.
  4. Generate graphics.Choose a visual template and the sizes you need for Facebook, Instagram, or Threads.
  5. Generate captions.Create drafts for selected platforms, edit them, and mark the versions you accept as Approved.
  6. Preview the website page.Use the SEO score to finish missing metadata, then inspect the private page preview.
  7. Download and publish manually.Download PNGs and copy approved captions. Meta publishing will be added later.
STEP 1

Create the lesson record

The lesson is the source of truth. Graphics, captions, and website exports are derived from it, so make corrections here first.

Title
The learner-facing topic. Make it specific enough to recognize in search.
Summary
One or two sentences describing what the learner will understand or build.
Difficulty
Beginner, intermediate, advanced, or mixed.
Category and tags
Used for organization, search, and eventual website discovery.
Series
Optional grouping for lessons that belong in a sequence.
SEO fields
Optional while drafting, but complete them before a website export.
Good first pass: title, summary, Draft status, difficulty, and category. Everything else can be refined later.
STEP 2

Build the lesson with content blocks

Select Add block on a lesson. Blocks can be edited, deleted, or moved with the up and down arrows.

ExplanationNormal teaching text.
CodeRunnable source code with preserved spacing.
OutputThe exact expected result.
HeadingA section divider inside a longer lesson.
Callout / tipA warning, shortcut, or important reminder.
ListSteps, rules, or related points.
QuizA knowledge check; optional JSON can hold choices and an answer.
ChallengeA task for the learner to complete.
ComparisonBefore/after or side-by-side concepts.
ImageA future-friendly image reference block.
Recommended order: short explanation → code → output → explanation or tip → challenge/quiz.
SOCIAL GROWTH

Use carousel templates for repeatable posts

The social carousel templates are designed for Code with Michael growth formats, not just generic lesson pages. Use them when you want a lesson to become a saveable or comment-friendly post.

Concept ExplanationA clear hook, plain-English idea, code, output, and takeaway.
Beginner MistakeA common error, why it happens, code to inspect, and fixing habit.
Spot the BugDebugging prompt that encourages comments and prediction.
Code Output QuizFollower predicts output before seeing the answer reveal.
Three Things to RememberA saveable reference post with three beginner reminders.
  1. Open a lesson and find Social carousels.
  2. Choose the format that fits the post idea.
  3. Optionally select output sizes and check Generate PNG assets now.
  4. Review the new blocks before posting, especially code and output.
Recommended cadence: use Concept Explanation for teaching, Beginner Mistake for saves, Spot the Bug and Code Output Quiz for comments, and Three Things to Remember for quick reference posts.
STEP 3

Generate downloadable graphics

  1. Open the lesson and find Generate assets.
  2. Choose the template that matches the lesson type.
  3. Select one or more output sizes.
  4. Select Generate graphics.
  5. Review every generated slide and use Download PNG for the versions you want.

Long content automatically flows across multiple slides. Generated files are also stored under media/generated/.

STEP 4

Draft and approve captions

  1. Select Facebook, Instagram, Threads, or any combination.
  2. Select Generate caption drafts.
  3. Read each draft for technical accuracy and tone.
  4. Select Edit or approve to revise the text.
  5. Change its status to Approved only when it is ready to use.
Cost control: each request records its model, tokens, duration, status, and estimated cost. Draft generation never publishes a post.
STEP 5

Record publishing and performance

  1. After posting manually, return to the lesson.
  2. Select Add publishing record.
  3. Choose the platform and enter the publish date, post URL, caption used, and graphic used.
  4. Add impressions, reach, likes, comments, saves, shares, clicks, follower growth, and follower count after posting when you have the numbers.

Saving a Facebook, Instagram, Threads, or Website publishing record marks that lesson's matching platform status as Published. The content calendar summarizes recent posts and platform totals.

Use this to learn what grows the brand: compare concept explanations, beginner mistakes, output quizzes, spot-the-bug posts, and reminders using actual post metrics.
EMAIL

Plan weekly newsletter campaigns

  1. Open Campaigns or draft an email from a lesson.
  2. Review the generated subject, preview text, body, and call to action.
  3. Set a scheduled date, audience segment, and estimated recipients.
  4. Send manually through your email platform.
  5. Return to the campaign, mark it Sent, and enter recipients, opens, clicks, unsubscribes, and bounces.

Campaigns can be connected to Email content plans and optional Email publishing records so email performance stays part of the same Code with Michael growth workflow.

Important: Content Studio plans and tracks newsletter emails. It does not automatically send email to subscribers.
EMAIL INTEGRATIONS

Check provider sync readiness

  1. Open Sync readiness from Studio navigation or visit /studio/newsletter/provider-readiness/.
  2. Filter by subscribers, segments, campaigns, provider, sync status, or readiness issue.
  3. Fix missing external IDs before manual or API-based syncing.
  4. Use Needs review and Error to keep provider mapping issues visible.
  5. Export the CSV when you need a checklist for Mailchimp, Beehiiv, ConvertKit, or another provider.

The report does not send or sync data automatically. It tells you what is mapped, what is ready, and what still needs provider IDs or review.

RESOURCE GROWTH

Add next-step CTAs to resource pages

  1. Open a resource in Studio.
  2. Review the Suggested CTA blocks panel for recommended matching lessons, quizzes, challenges, PDF downloads, and newsletter CTAs.
  3. Use Add CTA on a recommendation to create an editable CTA automatically, or use the manual Add CTA button.
  4. Use Dismiss when a suggestion is not a good fit; accepted, dismissed, and ignored suggestions are tracked in the CTA recommendation feedback report.
  5. Choose a target lesson for lesson, quiz, and challenge CTAs.
  6. Review the public resource page and confirm the button goes to the right next step.
  7. Open Resource CTAs and Recommendation feedback to compare clicks, conversions, completions, accepted suggestions, and dismissed suggestions.
Best use: every high-value cheat sheet should have one clear practice CTA. Recommendations are ranked by related lessons, category, learner level, active practice items, prior conversion history, feedback history, and the editable Tuning controls.
RECOMMENDATION ENGINE

Tune CTA recommendation scoring

  1. Open Tuning from Studio navigation or visit /studio/recommendations/tuning/.
  2. Use the built-in presets for Lead Magnet Growth, Lesson Completion, Quiz Engagement, or Challenge Practice when you want a fast strategic starting point.
  3. Open Simulate presets to compare side-by-side recommendations for a real resource before applying a preset.
  4. Adjust base bonuses to favor lessons, quizzes, challenges, PDF downloads, PDF lead magnets, or newsletter signups.
  5. Adjust lesson-match weights when you want related lessons, category, learner level, keyword overlap, clicks, or conversions to matter more.
  6. Adjust feedback weights when accepted, dismissed, or ignored suggestions should have a stronger or weaker effect.
  7. Add a short reason before saving when the change is tied to an experiment or brand-growth goal.
  8. Open Tuning history to review who changed weights, what fields changed, which preset was applied, and why.
  9. Save the active tuning profile and review a resource detail page to see the new base score, feedback adjustment, final score, and ranking notes.
Best use: run a simulation before applying a preset, then tune slowly. Raise one group of weights at a time, compare the suggestions before making another change, and use the audit log to retrace prior experiments.
STEP 6

Review performance reports

  1. Open Reports or visit /studio/reports/performance/.
  2. Choose a date range and optional platform filter.
  3. Compare content formats by reach, engagement rate, clicks, and new followers.
  4. Use the format-by-platform table to decide what to repeat next week.
  5. Download the posted-content, format summary, platform summary, or matrix CSV when you want to analyze the data in Excel or Google Sheets.

The report uses the connected content plan carousel format when available, then the graphic template, then caption-only/manual entry as a fallback. Planning posts before recording them produces cleaner reporting.

STEP 6

Preview and export the website lesson

  1. Review the Page readiness score and fix important warnings.
  2. Open Website preview in a new tab.
  3. Return to the lesson and select Create website export.
  4. Download HTML for a standalone page or JSON for future website integration.

Exports are numbered and immutable. Creating an export does not publish it to your existing website.

INTERACTIVE LESSONS

Enable the Python playground

  1. Edit the lesson and select Enable playground.
  2. Add at least one Code block that uses browser-compatible Python.
  3. Open Website preview and select Run code.
  4. Confirm the displayed output matches the lesson’s Output block.

The playground uses a version-pinned Pyodide runtime in a web worker. Learner code runs inside the browser, not on the Django server, and a runaway program is stopped automatically.

Use it for: Python fundamentals and supported browser packages. Avoid lessons that require local files, operating-system commands, desktop interfaces, private credentials, or a traditional server environment.

WHEN SOMETHING STOPS

Quick troubleshooting

The server is not running
Run .\scripts\run_local.cmd, leave that terminal open, and use a second terminal for other commands.
I cannot sign in
Use the email supplied to createsuperuser. There is no username.
Caption generation fails
Confirm OPENAI_API_KEY exists in .env. The failed run will be recorded in the dashboard ledger.
A graphic has too much content
Split large explanations into smaller blocks or allow the renderer to create a carousel.
My website export has warnings
Add a summary, content blocks, SEO title, SEO description, category, and tags.
I changed the lesson after exporting
Create a new website export revision. Older revisions remain available for comparison.

Experiment decision rules

The experiment decision rules page controls how Studio recommends keep changes, rollback recommended, or inconclusive from a tuning experiment snapshot.

Use the thresholds to decide how strong the before/after signal must be, and use the metric weights to emphasize the outcomes that matter most for Code with Michael growth: follower growth, resource downloads, newsletter clicks, CTA clicks, and learner conversions.

Experiment decision recommendations

After creating a recommendation tuning experiment snapshot, Studio now reviews the before/after deltas and suggests whether to keep the tuning change, roll it back, or mark the test inconclusive.

  • Keep changes appears when multiple growth signals improve after the tuning change.
  • Rollback recommended appears when several important signals decline after the tuning change.
  • Inconclusive appears when the signal is mixed, weak, or affected by too little activity.

The snapshot detail page shows positive signals, negative signals, confidence, a decision score, and a button to record the recommendation on the experiment outcome.
